# 바탕화면 플로팅 이미지 앱 — 정리 노트

요구사항, 단계별 체크리스트, 검토한 기술 이슈를 모은 문서입니다. 진행하면서 체크리스트를 갱신합니다.

---

## 1. 만들려는 것

- 바탕화면 위에 이미지(캐릭터)가 떠 있고, 화면 안을 돌아다닌다.
- 마우스(드래그, 클릭)와 키보드 단축키로 조작한다.
- 평소에는 정지 이미지를 보여주고, 특정 시점에는 GIF 같은 애니메이션으로 바꾼다.
- 모니터를 여러 대 쓸 때 특정 모니터에만 보이게 설정할 수 있다.

## 2. 전체 일정 예상

퇴근 후 틈틈이 진행하는 토이 프로젝트, 데스크톱 GUI 경험이 없는 백엔드 개발자 기준입니다.

| 단계 | 범위 | 예상 기간 |
|---|---|---|
| 1. MVP | 투명 창, 이미지 1장, 드래그, 단축키 숨기기/보이기, 트레이 종료 | 2~3일 |
| 2. 움직임·애니메이션 | 돌아다니기, 상태별 이미지 전환(PNG ↔ GIF) | +1주 |
| 3. 멀티 모니터 | 표시할 모니터 선택, 연결·해제 대응 | +1~2일 |
| 4. 완성도 | 클릭 통과, 설정 화면, 자동 실행, 설치 파일 | +1~2주 |

MVP(Minimum Viable Product)는 핵심 기능만 넣어 일단 동작하는 첫 버전입니다. 투명 창이나 항상 위처럼 기술적으로 막히기 쉬운 부분을 먼저 확인하려고 이렇게 나눴습니다.

## 3. 기술 스택 비교 — Electron으로 결정

| 스택 | 언어 | 맞는 경우 | 단점 |
|---|---|---|---|
| C# WPF / WinForms | C# | Windows에서만 쓸 때. 투명 창, 트레이, Win32 API 호출 자료가 가장 많음 | macOS 불가. WPF는 GIF 애니메이션을 기본 지원하지 않음 |
| Electron | JS/TS | macOS도 지원해야 할 때. `transparent`, `alwaysOnTop`, `globalShortcut`, `setIgnoreMouseEvents`가 기본 제공돼 MVP가 가장 빨리 나옴 | 메모리를 많이 씀(100MB 이상) |
| Tauri | Rust + JS/TS | Electron 방식이 좋지만 가볍게 만들고 싶을 때 | 네이티브 부분은 Rust로 작성 |
| JavaFX | Java | 익숙한 언어로 하고 싶을 때 | 전역 단축키는 JNativeHook, 클릭 통과는 JNA로 Win32를 직접 호출해야 해서 오히려 번거로움 |

추천: Windows 전용이면 C#, macOS도 필요하면 Electron으로 MVP부터 만들기.

**결정: Electron.** 빌드는 `@electron/packager`로 Windows x64 폴더를 만들어 zip으로 배포.

## 4. 단계별 체크리스트

### 1단계: MVP (2~3일) — 완료

- [x] 투명 배경, 테두리 없는 창 띄우기
- [x] 항상 위(always on top)
- [x] 작업표시줄에 창이 보이지 않게 하기
- [x] 투명 배경 PNG 이미지 1장 표시
- [x] 마우스 드래그로 이동
- [x] 전역 단축키로 숨기기/보이기 (앱에 포커스가 없어도 동작)
- [x] 트레이 아이콘과 메뉴 (보이기/숨기기, 종료)
- [x] 종료할 때 마지막 위치를 저장하고 다음 실행 때 복원

**완료 기준**: 실행하면 이미지가 바탕화면에 뜬다. 다른 창을 쓰는 중에도 단축키로 숨기거나 다시 띄울 수 있다. 트레이에서 종료할 수 있다.

### 2단계: 움직임과 애니메이션 (+1주) — 완료

- [x] 화면 안에서 돌아다니기 (현재 모니터 안의 근처 지점으로 이동, 방향에 따라 좌우 반전)
- [x] 상태(state)와 이미지 연결 구조 만들기 (아래 5장 참고)
- [x] 애니메이션 파일 형식 결정 → 형식은 사용자 자유(PNG, APNG, GIF, WebP), 앱이 ImageDecoder로 프레임을 풀어 canvas에 직접 재생
- [x] 1회 재생 애니메이션이 끝나면 idle로 되돌리기
- [x] 이미지 크기 통일, 또는 기준점을 하단 중앙으로 잡아 전환할 때 위치가 튀지 않게 하기
- [x] 시작할 때 애니메이션 이미지 미리 불러오기 (첫 전환 시 깜빡임 방지)
- [x] 사용자 캐릭터 폴더(`%APPDATA%\desktop-pet\pet`)로 교체, `pet.json`으로 크기·속도·잠드는 시간 설정

### 3단계: 멀티 모니터 (+1~2일) — 완료

- [x] 모니터 목록 조회
- [x] 메뉴(이미지 우클릭, 트레이)에서 표시할 모니터 선택: 자동 / 특정 모니터
- [x] 이동 범위를 선택한 모니터의 workArea로 제한
- [x] 선택한 모니터를 식별값으로 저장 (이름 +4, 위치 +2, 크기 +1 점수로 매칭, 3점 이상만 인정)
- [x] 모니터 연결·해제 이벤트 처리 (빠지면 주 모니터, 다시 연결하면 원래 모니터)
- [x] 다른 모니터로 드래그해 놓으면 설정을 그 모니터로 변경
- [x] 모니터별 DPI 배율 대응 (창 이동 시 크기를 함께 지정, canvas 해상도를 배율에 맞춤)
- [x] 음수 좌표 모니터 계산 (단위 테스트)
- [x] 이동을 화면 갱신 주기에 맞춤: 렌더러의 requestAnimationFrame마다 메인 프로세스에 신호를 보내 위치 계산
  - 33ms setInterval은 Windows 타이머 정밀도(약 15.6ms, 배터리 모드에서 더 불규칙) 때문에 노트북에서 끊겨 보였음
- [x] Windows 다중 모니터에서 확인

### 4단계: 완성도 (+1~2주)

진행 순서: 4-1 기능 → 4-2 설정 화면 → 4-3 설치 파일. 각 묶음마다 Windows 확인 후 커밋.

**4-1**
- [x] 이미지의 투명 영역은 클릭이 뒤로 통과
  - 시작은 `setIgnoreMouseEvents(true, { forward: true })`로 클릭 통과
  - 메인 프로세스가 매 프레임 커서 위치(창 기준)를 렌더러에 보내고, 렌더러가 현재 프레임의 알파값으로 판정해 통과 여부를 바꿈
  - 마우스가 움직이지 않아도 캐릭터가 커서 아래로 걸어오거나 프레임이 바뀌면 판정이 달라지므로 매 프레임 확인
- [x] 전체 화면 앱 실행 중 자동 숨김 (결정: 자동 숨김, 메뉴에서 끌 수 있음)
  - Electron에 기능이 없어 koffi로 user32.dll 호출: 맨 앞 창의 크기가 모니터 bounds와 정확히(±2px) 같고, 바탕화면·작업표시줄이 아니면 전체 화면
  - 처음엔 "최대화 창 제외(IsZoomed)" 규칙을 썼으나, Chrome은 최대화한 채 전체 화면에 들어가면 계속 최대화로 표시되어 감지 실패. 최대화 창은 보이지 않는 테두리 때문에 모니터보다 사방 8px 커서 크기로 구분
  - 캐릭터가 있는 모니터만 확인. 사용자가 숨김 중에 다시 보이게 하면 그 전체 화면이 끝날 때까지 자동 숨김 안 함
- [x] OS 시작 시 자동 실행 (`app.setLoginItemSettings`, 빌드한 exe에서만)

**캐릭터 이미지 여러 개**
- [x] 같은 상태에 `상태이름_아무거나.확장자`로 이미지를 여러 개 두면 그 상태가 될 때마다 무작위로 하나 재생 (직전 이미지 제외)
  - 계기: 대표 이미지 1개를 클릭하면 움직이는 이미지 5개 중 하나를 무작위로 보여주는 캐릭터(검은 고양이) 적용
- [x] 검은 고양이 캐릭터: 외부 이미지 대신 곰과 같은 그림체로 코드로 그림 (`assets/pets/cat`, 클릭 5종: 점프·흔들기·꼬리·갸웃·하트)
  - 기본 캐릭터는 곰 유지, 고양이는 설정 화면에서 선택

**4-2**
- [x] 설정 화면: 캐릭터 선택, 크기, 이동 속도, 잠드는 시간, 단축키, 표시할 모니터, 전체 화면 숨기기, 자동 실행
  - 저장 버튼 없이 바꾸면 바로 적용·저장. 메뉴 등 설정 창 밖에서 바뀐 값도 메인 프로세스가 설정 창에 다시 보내 줌
  - 크기·속도·잠드는 시간은 설정값이 null이면 캐릭터 pet.json 값 사용 ("기본값으로")
  - 단축키 입력 중에는 기존 단축키를 해제 (전역 단축키로 등록된 조합은 설정 창에 키 입력이 오지 않음). 등록 실패 시 원래 단축키 유지
- [x] 실행 중 캐릭터 교체 (재시작 없이), 폴더 추가, "다시 불러오기"
  - 렌더러는 새 캐릭터 이미지를 다 디코딩한 뒤 한 번에 바꿈 (그동안 이전 캐릭터 표시)
  - 크기가 바뀌면 발 위치(하단 중앙)를 고정한 채 창 크기 변경
- [x] 트레이 아이콘을 현재 캐릭터의 대표 이미지로 (렌더러가 첫 프레임을 16·32px PNG로 만들어 보냄. nativeImage가 GIF·WebP를 못 읽기 때문)
- [x] Windows에서 확인

**4-3**
- [x] 설치 파일 만들기 (결정: NSIS 설치 프로그램 - 시작 메뉴·바탕화면 바로가기, 제거)
  - electron-builder, 현재 사용자 설치(관리자 권한 불필요), 설치 위치 변경 가능, 한국어 설치 화면
  - 앱 아이콘: 곰을 16~256px 크기별로 다시 그려 .ico 생성 (128px 이미지를 늘리면 흐려짐)
  - 설정 폴더를 `%APPDATA%\desktop-pet`으로 고정: 설치판은 productName("Desktop Pet")이 앱 이름이 되어 폴더가 바뀌므로, 압축판 설정을 이어 쓰도록 `app.setPath('userData')`로 지정
  - 제거해도 설정 폴더는 유지
  - Chromium 언어 파일은 한국어·영어만 포함
  - Linux에서 빌드하려면 Wine(32비트 포함) 필요: 제거 프로그램을 만들 때 32비트 NSIS 설치 프로그램을 실행하기 때문
  - Wine에서 설치·제거를 확인함 (파일, 바로가기, 앱 목록 등록·삭제, 설정 폴더 유지). Wine에서는 "앱 실행 중" 검사가 항상 실행 중으로 잘못 판단해서, 검사를 끈 테스트 빌드로 확인
- [x] Windows에서 확인

## 5. 상태별 이미지 전환 설계

평소에는 정지 이미지(PNG)를 보여주고, 이벤트가 생기면 애니메이션으로 바꾼 뒤 끝나면 돌아옵니다. 상태마다 이미지를 연결해 두면 상태를 추가하기 쉽습니다.

| 상태 | 이미지 | 재생 | 전환 조건 |
|---|---|---|---|
| idle | `idle.png` | 정지 | 기본 상태 |
| walk | `walk.gif` | 반복 | 이동 중일 때 |
| click | `jump.gif` | 1회 → idle | 클릭했을 때 |
| sleep | `sleep.gif` | 반복 | 입력 없이 10분 지났을 때, 또는 특정 시각 |

전환 조건으로 쓸 수 있는 것: 클릭, 단축키, 타이머, 시각, 이동 여부, 마우스 접근.

### GIF를 쓸 때 문제와 대안

| 문제 | 원인 | 해결 |
|---|---|---|
| 재생이 끝난 시점을 알 수 없음 | `<img>`, WPF 모두 GIF 재생 종료 이벤트가 없음 | 프레임별 지연 시간을 읽어 총 재생 시간을 계산하고 타이머로 되돌림 (Electron `gifuct-js`, C# `Image.GetFrameCount` + `PropertyTagFrameDelay`). 또는 스프라이트 시트로 프레임을 직접 넘김 |
| 테두리가 계단처럼 보이거나 흰 테두리가 남음 | GIF는 반투명 픽셀이 없음 (완전 투명 / 완전 불투명만 가능) | 반투명 테두리가 필요하면 APNG 또는 애니메이션 WebP 사용 (Electron은 둘 다 지원) |
| 같은 GIF를 다시 지정하면 중간부터 재생됨 | 이미지 캐시 | Electron에서는 `src`에 쿼리 문자열을 붙여 새로 불러옴 |
| WPF에서 GIF가 움직이지 않음 | 기본 미지원 | `WpfAnimatedGif` 또는 `XamlAnimatedGif` 라이브러리 |
| 전환할 때 캐릭터 위치가 튐 | idle과 GIF의 이미지 크기가 다름 | 크기 통일, 또는 하단 중앙 기준으로 창 위치 보정 |

데스크톱 펫 류 프로그램은 재생 위치와 종료 시점을 코드에서 제어할 수 있어서 스프라이트 시트를 많이 씁니다.

## 6. 멀티 모니터 설계

연결된 모니터 목록을 가져와서, 창의 위치와 이동 범위를 선택한 모니터의 영역 안으로 제한합니다.

### 모니터 목록 조회 API

| 스택 | API |
|---|---|
| Electron | `screen.getAllDisplays()` — 각 모니터의 `bounds`, `workArea`, `scaleFactor` |
| C# | `Screen.AllScreens` — `Bounds`, `WorkingArea`, `DeviceName` |
| Win32 | `EnumDisplayMonitors`, `GetMonitorInfo` |

- bounds: 모니터 전체 영역
- workArea: 작업표시줄을 뺀 영역 (이동 범위는 이 값 기준)

### 동작 방식 결정 사항

- 사용자가 다른 모니터로 드래그했을 때: 놓는 순간 원래 모니터로 되돌릴지, 그 모니터로 설정을 바꿀지
- 여러 모니터에 동시에 표시해야 한다면 모니터마다 창을 하나씩 띄우는 편이 좌표 계산이 단순함

### 주의할 부분

- **식별값이 바뀜**: 케이블을 다시 꽂거나 도킹을 바꾸면 모니터 순서와 ID가 바뀔 수 있습니다. 순서("2번 모니터")로 저장하면 엉뚱한 화면에 뜨므로, 장치 이름이나 해상도·위치 조합으로 저장하고 일치하는 모니터가 없으면 주 모니터를 씁니다.
- **실행 중 연결·해제**: 모니터를 빼면 창이 보이지 않는 좌표에 남습니다. 이벤트를 받아 위치를 다시 잡습니다.
  - Electron: `display-added`, `display-removed`, `display-metrics-changed`
  - Windows: `WM_DISPLAYCHANGE` 메시지
- **모니터별 DPI 배율**: 100% 모니터와 150% 모니터가 섞여 있으면 창을 옮길 때 크기와 좌표가 틀어집니다. Windows에서는 Per-Monitor DPI Aware를 켭니다.
- **음수 좌표**: 주 모니터 왼쪽·위쪽 모니터는 좌표가 음수입니다. 좌표를 0 이상으로 가정한 경계 계산은 여기서 깨집니다.

이 기능에 드는 시간(1~2일)은 대부분 연결·해제 처리와 식별값 저장에 들어갑니다.

## 7. 막히기 쉬운 부분 요약

| 항목 | 내용 |
|---|---|
| 클릭 통과 | 이미지의 투명한 영역 클릭이 뒤 창으로 가야 함. OS API를 직접 호출하는 경우가 많음 (Windows `WS_EX_TRANSPARENT`, layered window). 애니메이션이면 판정용 알파 마스크를 현재 프레임 기준으로 갱신해야 함 |
| 전역 단축키 | 앱에 포커스가 없어도 동작하려면 OS 레벨 등록이 필요함. 다른 프로그램이 쓰는 조합이면 등록이 실패함 |
| 멀티 모니터·DPI | 6장 참고 |
| 배포 | 코드 서명 없이 배포하면 Windows SmartScreen 경고가 뜸. 혼자 쓰면 무시해도 됨 |
| CPU 사용량 | 애니메이션 루프를 계속 돌리면 노트북 배터리를 먹음. 숨김 상태일 때는 루프를 멈출 것 |
